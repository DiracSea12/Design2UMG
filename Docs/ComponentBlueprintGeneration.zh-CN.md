# 一次导入父子控件蓝图：当前实现与边界

本文说明已实现的行为与仍有的缺口，不代表已通过完整验收。

## 输入与拆分

- 使用保留组件依赖信息的 Figma 导出数据。离线导入需要 `design.json` 和对应的 `images`；组件定义、实例身份和已展开的实例子树都需要保留。
- 不含组件引用的有效空依赖包仍走普通 Import，重名时另建资产；组件批次才按稳定身份原位更新。
- 按组件与实例引用递归生成依赖，先子后父。普通 Frame、Group 继续作为布局容器，不按图层深度拆资产。
- 用户指定的已有 WBP 映射优先于自动生成；沿用现有组件级、组件集级映射规则。

## 资产与实例

- 每个组件在本次目标目录与源身份范围内生成一份独立 WBP，多处引用创建多个实例。身份来自文档范围及组件键，不依赖显示名称。组件集映射使用发布键 `componentSetKey`，节点定位字段 `componentSetId` 不充当发布键。
- 每个变体是独立资产。首次生成按组件集分目录；以后组件换所属集合，继续使用已有资产路径，避免重复生成和破坏引用。发现同一稳定资产名对应多条路径时报告冲突，不自动选取或删除。
- 生成类使用 UE 原生 `UUserWidget` 和 `NamedSlot`（供实例替换局部内容的插槽），不依赖编辑器专用控件类。
- 文本内容、显隐、组件替换及已转换的布局/外观差异，通过实例的局部内容保存。共享子类并不意味着共享所有实例显示值。

## 重导入与失败

- 整套组件从首次导入生成的父 WBP 发起重导入，子 WBP 随依赖顺序一起更新。直接选择子 WBP 或其侧车记录时，入口会提示选择父 WBP，并保留子资产原状；子 WBP 仍是独立可复用资产。

- 子组件 WBP 按整份生成资产管理；父页面 WBP 按节点所有权更新。旁边的 `.d2u.json` 保存源身份、生成节点及组件批次关系，子组件另存文件校验信息。
- 父页面复用安全重导入的节点合并：更新设计内容，保留已保存的用户事件图、变量和手工控件。子组件手工修改、页面尚未保存、记录缺失或身份冲突会明确报告。实例覆盖内容若包含用户控件或用户逻辑引用，整批回滚，保留原资产。
- 依赖不可访问、图片缺失、构建或编译失败均报告受影响项，不把缺失依赖当作完成。
- 资源准备失败和根尺寸错误保留具体原因；子组件错误带稳定组件身份。提供源文档的导入即使没有生成资产，也会在项目 `Saved/Design2UMG/ImportReports` 写出报告。仅生成 WBP、同时生成预览图、同时生成编译后截图三条路径均传递这些诊断。
- 构建失败恢复已修改的 WBP 内存状态；批量保存失败恢复 WBP 文件及生成记录，并清理部分输出。写入前检查所有 WBP 与生成记录的可写性。已有父子控件共同使用一次编辑器撤销记录；保存失败撤回本批次，不清空用户已有的撤销记录，也不留下失败批次供重做。构建返回前已关闭事务，不跨调用悬挂编辑器事务。
- 若调用方把构建和保存分开，并在两者之间加入其他编辑操作，保存失败会报告自动撤销受阻，保留这些后续操作；恢复自身失败同样明确报告。派生贴图等其他资源不属于这项 WBP 批量恢复保证。

## 尚未完成的验收与限制

- 已有测试覆盖多层嵌套、同组件多实例、变体及替换、实例显隐、已有映射优先、保存后重载、冲突保护、失败恢复和组件换组。
- `Design2UMG.ComponentBlueprintPersistence.GameplayPIE` 在真实项目的临时未保存地图中启动游戏，将已保存的父 WBP 加入游戏视口，检查子实例、共享类、文字覆盖及实际布局，并保存含 UMG 的游戏窗口截图。默认使用 `SharedInstances` 用例留下的资产；指定资产时需同时传入 `-D2UComponentPIEAsset=<资产路径>` 和 `-D2UComponentPIEExpectedChildren=<直接子实例数>`。已验证共享实例样本和真实 HUD（5 个直接子实例）；这不代表打包验证或全部视觉验收通过。
- Figma 的 `characterStyleOverrides` / `styleOverrideTable` 已接入连续文字片段，保留片段的字体、字重、字号及单色覆盖；末尾省略的默认样式索引按默认样式处理，UTF-16 索引按源定义解析，不拆开一个完整的表情字符。混合颜色与跨行文字已有渲染测试。
- 混合文字样式已完成独立进程的保存重载验证：先运行 `Design2UMG.ComponentBlueprintPersistence.RichTextSave`，退出编辑器后再运行 `RichTextReload`。测试检查共享子类、每个实例独立的样式表、字体对象、颜色、粗体和字号，并验证保存前后全部渲染像素一致；新进程要求由测试中的进程编号断言保证。
- 逐片段行高、渐变或多层文字填充等仍未完整支持，会报告受影响节点与样式；异常索引、字段类型和数字范围也会报告。异常样式不发布半截文字片段列表。上述诊断不等于这些样式已正确显示，仍需完成处理方案确认与对应验收。
- 父、子蓝图生成前会自动导入本机可用字体；本机仍缺少所需家族或字重时，会报告缺失和替换情况。成功生成蓝图不等于字体及视觉已经一致。
- 当前代码与已补齐字体的 81-case 全量结果，结合两项异常样例的独占串行复测，四项绝对指标均不低于正式 `d4-seal81-20260906_01` 基线，结构检查全部通过。原始分片报告与复测报告分别保留；这不代表逐项历史最佳，也不代表上述覆盖限制已经解决。
- 本功能不新增或推断游戏业务逻辑、动画或 Figma 原型交互。

## 本地字体默认导入

- 生成父、子 WBP 前，按文本节点及文本片段实际使用的家族、字重、斜体和 PostScript 身份准备字体。
- 用户明确配置的字体映射优先，不自动修改映射目标。已有项目字体包含所需字重时直接复用。
- 源文件优先查插件 `Fonts/`；随后查项目 `Saved/Design2UMG/ManualFonts`、`Saved/Design2UMG/figma-font-candidates`、引擎字体目录和 Windows 系统/用户字体目录。不扫描测试字体目录，不下载字体。
- 匹配依据字体内部信息，不以文件名认定家族。内部字重与样式名称冲突的文件跳过。
- 新建家族资产默认位于项目 `Content/Design2UMG/Fonts`。字体数据作为内嵌 UFontFace 保存，已有家族只补缺少的字重；重复导入复用已有资产。
- 当前自动导入支持标准宽度的静态单字体 TTF/OTF；集合字体、可变字体需要提供对应的静态单字体文件。源声明尚未表达字宽，因此不把窄体或宽体文件自动当成标准宽度字体。缺失的具体家族/字重写入导入诊断，现有替代字体规则继续适用，不能把它视为视觉一致。
- 字体资产保存失败会中止对应导入并返回原因。此次接入不代表游戏打包或完整视觉验收已通过。

## 本轮实现补充

- 本地 Figma 导出保留字符样式片段和 UTF-16 索引，包括混合字体、字号、字重、颜色、字距和行高字段。不同大小写转换等尚未支持的片段属性进入诊断，节点目标超链接也明确报告。数据保留不等于所有片段属性已达到视觉一致。
- 同一组件批次的本地字体文件只建立一次索引；下一次导入重新发现文件，避免新增字体被永久缓存挡住。
- 子树阴影保留三倍标准差的范围，宽阴影采用有界采样网格，精确对齐的单位网格每层每像素最多 1089 次读取；其他网格沿用原离散积分，最坏仍为 4225 次（另有一次原内容读取）；只在实际纹理坐标是相邻像素中心时合并加权读取；分数位移、缩放和宽步长不会走该快速路径。宽阴影的原有稀疏积分仍是近似，不宣称任意图案与密集卷积一致。已有运行测试对 32/100 模糊半径与密集高斯参考进行比较。
- 图像报告的双透明像素归零改由 Pillow 批量执行，3×3 最大值/最小值滤波改成数学等价的横向、纵向分步处理；透明规则、评分公式、阈值和参考图保持原样，回归数量仍由发现结果计算。

### 身份、映射失败与槽内容保护

- 稳定资产名按完整源身份的 UTF-8 字节计算；中文等字符参与区分，ASCII 身份的命名结果保持一致。
- 用户指定的 WBP 类加载或创建失败时，报告 `mapping_class_unavailable`，将源数据中提供的该实例子树按普通控件转换；其内部不再尝试自动生成未规划的组件资产。此结果是带诊断的普通转换，不代表指定的 WBP 映射成功。未被显式映射覆盖的缺失依赖仍按组件批失败处理。
- 普通转换的实例也写入生成记录，供后续重导入更新，避免映射失败后丢失源与控件的对应关系。
- 更新依赖前先检查父页面生成实例的旧槽内容；槽内有手工控件、事件图引用或绑定时报告冲突，保留原资产。检查发生在子组件编译前，覆盖新类删除槽以及设计删除整个实例的情况，避免保存阶段清除旧绑定。

### 重导入边界与字体扫描

- 自动补充字重或斜体只写入 `/Game/Design2UMG/Fonts/`。目录外的项目字体仍可按既有规则引用，但不会被自动改写；缺少请求样式时，报告会列出字体资产、字重及斜体要求。显式字体映射始终保持只读。

- 同名嵌套节点按剩余候选的创建顺序一一配对，重复导入保留原控件对象，不跳过第二个同名节点。
- 所有权检查复用 UE 的子树遍历，覆盖普通容器和 Named Slot 的内容；用户动画的控件及布局槽绑定也参与保护。插件生成的导航动画沿用现有生成归属规则，仍由生成器更新。
- 显式组件映射即使创建失败，也不会再被名称型 ClassOverride 改写；失败子树执行普通转换并报告诊断。
- 每次字体索引仍重新发现目录中的文件；同一编辑器进程只复用大小和修改时间均未变化的已成功解析字体元数据，不缓存字体字节。新增、删除、修改会在下一次导入发现；读取失败的文件仍重试，避免一次临时失败长期保留。当前正在进行的一次导入使用自己的固定索引。若外部工具改写字体时刻意保留大小及修改时间，应重新启动编辑器再导入。

## 本轮质量收缩

组件目录定位在每批导入开始建立一次临时索引，按稳定资产名查询；不增加跨次导入缓存。富文本样式行不再输出运行时未使用的 DesignFontSize 字段；节点层面的源字号诊断保留。弱参考来源仍必须阻断验证，不能借输入身份升级放宽参考权威要求。
