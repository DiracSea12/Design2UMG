# Known Limitations

This document tracks currently confirmed limitations in Design2UMG.

Last verified: 2026-03-05 (source-level review + local automation tests).

## Path Rasterization

- Path texture cache key is a 32-bit hash (`uint32`), so collision is still theoretically possible (very low probability).
- Path fitting currently applies uniform scale (`min(scaleX, scaleY)`), so some non-uniform stretch scenarios may differ from source design tools.

## Shadow and Effect Fidelity

- Shadows can still be clipped by parent widgets using strict clipping (`ClipToBounds*`).
- Box shadows are generated by procedural blur textures (good preview quality), not physically accurate lighting.
- Foreground blur effects are ignored (UMG has no direct foreground blur equivalent in this pipeline).
- Inner shadows are ignored.
- `TextBlock` effectively supports a single shadow; multiple text shadows are not preserved one-to-one.

## Ellipse / Vector Fidelity

- Ellipse/vector edge cases still have fallback paths.
- Example: ellipse with stroke may degrade to rounded-rect style fallback instead of true vector stroke parity.
- Polygon/line/path nodes without valid geometry may degrade to simpler widget output.

## Font Assets

- Design metadata carries font names/URLs, not embedded font binaries.
- Auto-import/mapping exists for known fonts and icon fonts, but full automatic reconstruction of all project font families is not guaranteed.

## Interaction and Animation

- Figma/Pen interaction/prototype fields are parsed into metadata, but not converted to runtime UMG behavior.
- UMG animation timeline assets are not auto-generated.
